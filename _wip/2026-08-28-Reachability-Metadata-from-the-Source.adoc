== The condition schema cannot express a per-OS choice

The condition mechanism has an interesting limitation. A condition can only name a Java class. That is sufficient for windowed applications, because each operating system has its own glass `Application` class, so anchoring `DWFactory` to `WinApplication` encodes "only on Windows" indirectly. However, this breaks down for the first user that is not OS specific, which is the built-in headless platform:

`HeadlessApplication` is one class on every OS. `PrismFontFactory` selects the backend based on `isWindows`/`isMacosx`/`isLinux`, which native-image folds at build time, so a headless image reaches exactly one of the three backends. However, there is no platform-specific class underneath `HeadlessApplication` to attach a condition to, and registering all three backends fails the link as described above. What the metadata would need to express is simply `"condition": {"os": "windows"}`, which no schema version currently offers. Note that the newer https://www.graalvm.org/latest/reference-manual/native-image/metadata/[unified metadata format] (1.2.0) actually made this worse: the older `typeReachable` condition is a build-time question, evaluated after the OS has been folded away, while its replacement `typeReached` is a runtime question and the only remaining vocabulary. This is why the metadata ships in the older format, and a build-time platform condition seems like a reasonable upstream request that would benefit anyone publishing cross-platform metadata.
